Console layout — three options for the area above Browse & edit

Today that area is five equally-weighted cards, ten stat tiles and a paragraph under every heading: 1,432px before the work starts, on a 1,000px screen. Each option below shows the same real state — 8,398 terms, 440 open issues, 27 unpublished changes, repository connected — so they can be compared directly. Non-functional mockups; buttons do nothing.

Option A

Status strip

Everything collapses into one dense line under the masthead. Numbers sit inline rather than in tiles, and the explanatory paragraphs go entirely — they taught you the model once and then repeated themselves forever. Anything needing attention appears as a single band beneath; when nothing does, that band is absent and the work begins immediately.

~96px before Browse & edit — a 93% reduction.

Option B

Left rail

Status moves sideways instead of down. The page is 1,600px wide and currently uses none of that for context, so this reclaims horizontal space rather than competing for vertical. The rail stays visible while scrolling a long list, which the stacked cards do not — today you scroll past the draft count and then cannot see it while working.

What they have in common

All three drop the explanatory paragraph under each heading, and all three stop giving a zero the same visual weight as 8,398. Today the draft section reserves four large tiles that read 0, 0, 0, 0 for most of a release cycle, which is where a lot of the heaviness comes from.

They differ in what happens when nothing needs attention. A disappears almost entirely. B keeps everything permanently visible but out of the way. C keeps today's structure and just folds it up.
